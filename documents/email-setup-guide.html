Website maintenance

Estate Resolve email via Brevo

The expired SendGrid trial has been removed from the website entirely. All outgoing email now goes through Brevo's SMTP relay, free at this volume. This is the runbook for finishing the switch.

What this covers

Every email the website sends automatically — eight in total, across contact enquiries, solicitor enquiries, case intake, consultation bookings and Stripe payments. Each type sends a confirmation to the customer and a notification to the operations inbox.

Receiving is untouched. The domain's existing mailboxes carry on exactly as they are; nothing in this setup changes where incoming mail lands.

Already done

In the code

SendGrid fully removed

  • @sendgrid/mail uninstalled
  • Fallback code and SENDGRID_* config deleted
  • app/lib/email.ts is SMTP-only
  • Customer address set as Reply-To on admin emails

In DNS

Domain records already published

  • brevo-code verification record is live
  • Both DKIM keys resolve at dkim.brevo.com
  • Nothing further needed at the registrar

Because the DNS half is already in place, what remains is account confirmation, one key, and the deploy.

The remaining steps

1

Confirm the Brevo account

Sign in at app.brevo.com. If the account does not exist yet, sign up free at brevo.com using the Estate Resolve address — no card is required at this volume.

2

Check the domain shows as authenticated

Go to Senders, Domains & Dedicated IPs → Domains. The entry for estateresolve.co.uk should show green ticks for domain verification and DKIM.

The DNS records these check for are already published, so this should pass on sight. If it shows as pending, use Brevo's own Verify button rather than re-adding any records.

3

Verify contact@estateresolve.co.uk as a sender

Under Senders, add contact@estateresolve.co.uk if it is not listed. Brevo emails a confirmation link to that mailbox, so you need access to it to click through.

4

Generate the SMTP key

Account menu (top right) → SMTP & API → SMTP tab, or go straight to app.brevo.com/settings/keys/smtp.

Where each value comes from
VariableFound as
SMTP_USERthe "Login" field — an email address
SMTP_PASSthe SMTP key value — not your account password

Handle the key like a password

Anyone holding it can send mail as Estate Resolve. It belongs in .env.local locally and in Vercel's environment variables in production — never in git, and never pasted into a chat or ticket.

5

Set the environment variables

Same eight values locally in .env.local and in Vercel:

Vercel → Settings → Environment Variables (Production)
VariableValue
EMAIL_PROVIDERsmtp
SMTP_HOSTsmtp-relay.brevo.com
SMTP_PORT587
SMTP_SECUREfalse
SMTP_USERfrom step 4
SMTP_PASSfrom step 4
SMTP_FROM_NAMEEstate Resolve
SMTP_FROM_EMAILcontact@estateresolve.co.uk

Delete the old SENDGRID_API_KEY and SENDGRID_FROM_EMAIL entries in both places while you are there — the code no longer reads them.

6

Redeploy

Vercel does not apply environment changes to a running deployment. Trigger a new production deploy after saving the variables, or nothing changes.

7

Test the connection, then a real send

  • npm run email:test — authenticates against Brevo and stops.
  • npm run email:test -- you@example.com — sends a real message.
8

Exercise every form on production

Each of these should produce two emails — one to the customer, one to operations:

  • Contact form
  • Solicitor enquiry form
  • Case intake form
  • Consultation booking
  • Stripe payment (use a test-mode payment)

One thing to watch

The domain quarantines unauthenticated mail

estateresolve.co.uk publishes DMARC p=quarantine, and Brevo is not listed in the domain's SPF record — so DKIM alone carries authentication. It is correctly configured for that, but it means there is no second line of defence.

On your first real test, open the received message's headers and confirm dkim=pass with d=estateresolve.co.uk. If it fails, mail will be quarantined silently rather than bouncing, so the website will report success while nothing arrives.

Done when

  • Brevo shows the domain authenticated and contact@estateresolve.co.uk verified as a sender.
  • The eight variables are saved in Vercel and a fresh deploy has run.
  • A real production form delivers both the customer confirmation and the admin notification.
  • Replying to an admin notification reaches the customer, not Estate Resolve.
  • Headers on a delivered message show dkim=pass.

Ongoing

Brevo's free tier allows 300 emails a day. Each enquiry uses two, so that is roughly 150 enquiries daily before any cost — well beyond current volume. The dashboard shows the running count on its front page.
